# git指令大全
------------
## 初始化仓库
* git init （"路径"）：将当前的文件夹变为受git控制的文件夹（仓库）。
* git clone "github上链接"：将github上的repo下放到文件夹下形成git文件夹

## 添加和提交文件
* git add "route"：将route的文件放入暂存区
==git add . ：将所有修改和新添加的文件加入暂存区==

* git commit -m "本次提交的命名"：将暂存区中的文件提交入仓库
* git commit -a -m "...." :同时做到暂存然后提交。**但不会暂存untracked文件，而是modified文件**
==如果是只有git commit：进入nano或vim编辑器来提交暂存区的文件==

* git log：查看所有的提交记录和对应的提交特征码
==如果是git log --oneline：简要的查看所有提交记录==

## 回退版本与恢复文件
* git reset <回退模式> <提交特征码> ：用于回退到历史提交时的状态（根据回退模式选择是否保留当前工作区、暂存区状态（是否一起被重置））

| 回退模式 | 工作区保留 | 暂存区保留 |
| :---------: | :---: | :---: |
| --soft | √ | √|
|--mixed（默认模式）|√|×|
|--hard|×|×|
* git checkout -b <已删除的分支名称> <需要恢复到哪一次的提交状态的哈希值> ：创建一个新分支，与指定的那个分支和提交一致（看起来像是恢复了原来的那个分支），并移动到这个新分支
* git branch <分支名> <提交哈希> ：与上一条功能类似，但不会切换到这个新分支，也完全不影响当前的状态，包括工作区，暂存区等。

## 查看差异
* git diff：工作区 与 暂存区的差异
* git diff HEAD：工作区+暂存区 与 仓库的差异
* git diff --cached：暂存区 与 仓库的差异

## 删除文件
* rm + add指令：rm < file> 删除工作区route路径的文件;后采用git add指令同步到暂存区，实现暂存区和工作区删除文件
* git rm <"file">：删除工作区和暂存区的文件
* git rm --cached < file>：删除暂存区的文件，但保留工作区的文件（也就是只删掉在版本库中的文件，但不会删掉本地文件）
* git rm -r *：递归删除目录下的所有子文件和子目录

==删除完文件后都需要commit，才能将删除同步到仓库==

## 忽略文件
.gitignore 文件，内部存储着需要被忽略的文件，
>一般需要被忽略的文件如下：
>-系统自动产生的文件
>-编译产生的中间文件和结果文件
>-运行时生成的临时文件，日志文件，缓存文件等
>-含有密码，个人信息，key等私密或敏感的文件

编写.gitignore文件的规则：
* #符号负责当作注释
* 正则表达式编写表达要忽略的文件

对于一些更复杂的规则和忽略，可以了解git的hook文件

## 分支相关
### 相关指令
* git branch：查看当前仓库的所有分支(标绿部分代表当前所在分支)
* git branch <分支名称>：创建一个新分支
* git checkout <分支名称>：切换到分支；==等价于 git switch <分支名称>==
  >git checkout 还可用于恢复文件，因此checkout的命令可被分为两部分，切换分支指令switch。恢复指令restore。
* git merge <要被合并的分支> ：将指定分支合并到当前所在的分支
* git merge --abort：中断本次合并。
* git rebase <分支名> ：将当前分支嫁接到指定分支上 ==变基就是给当前分支变换基础==

|类别| rebase | merge |
|:---:| :---: | :---: |
|优点| 不需要新增额外的提交记录到目标分支，形成直观干净的线性分支图 | 不会破坏原分支的状态，提交历史等，方便查看|
|缺点|会改变提交历史，不要在共享分支上使用|分支图会变得复杂，产生额外的提交节点（合并时的提交）|

* **删除分支**
  * git branch -d <分支名>：删除已被合并后的分支
  * git branch -D <分支名>：强制删除分支（无论是否被合并过）

### 解决合并冲突
  **当合并的两个分支中相同的文件出现不一致时就会造成合并冲突，git无法确定我们需要哪一个分支中的文件**
  git merge合并后在当前分支内我们文本编辑器（vscode）查看冲突文件会发现既有当前分支的修改和合并分支的修改，只需要在其中编辑保留我们需要的部分，然后保存，add然后commit即可解决冲突

## 分支管理规范
* 分支命名：使用带有实际意义的名称（版本号，对应问题修复，分支实现功能等）
* 分支管理：
  * 定期合并已经成功验证的分支，及时删除已经成功合并的分支
  * 保持合适的分支数量
  * 为分支设置合理的权限

### 关联本地仓库和远程仓库
添加远程仓库：
>git remote <远程仓库别名（自行命名）> <远程仓库地址>
>git push <远程仓库名> <本地分支名>:<远程分支>

查看远程仓库：
>git remote -v

拉取远程仓库内容（并自动合并，如果没冲突的话）：
>git pull <远程仓库名> <远程分支名>:<本地分支名>
